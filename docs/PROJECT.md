# О проекте «Моя аудиокнига»

## Идея и цель

Аудиокнигу можно записать самостоятельно, но чтение большого текста требует
времени. В этом проекте исследуется другой путь: подготовить образец своей
речи, сохранить текст и попробовать озвучить его локальной моделью.
Студия объединяет подготовку материалов, запуск обработки и прослушивание
в одном интерфейсе.

Его цель — собрать работающую цепочку от исходных
материалов до WAV и понять ограничения такого подхода. Получить файл,
похожий на речь, и точно передать голос конкретного человека — разные
задачи. Вторая пока не решена до приемлемого результата.

Основные задачи проекта:

1. Хранить текст, запись и результаты в отдельном проекте.
2. Подготавливать русский текст и позволять исправлять произносимую версию.
3. Запускать озвучивание небольшими фрагментами и показывать состояние работы.
4. Готовить проверенный набор записей для дообучения.
5. Сохранять обучение и продолжать его после остановки приложения.
6. Давать возможность сравнивать пробы перед озвучиванием большой книги.

## Как устроена работа

Приложение предназначено для Windows x64. При запуске оно поднимает локальный
сервер на `127.0.0.1` и открывает интерфейс в обычном браузере. Порт выбирается
при запуске. Доступ к интерфейсу связан с локальной сессией приложения.

Обычный порядок действий выглядит так:

1. Создать проект и загрузить запись в WAV.
2. Выбрать чистый голосовой фрагмент, прослушать его, указать точные слова
   и подтвердить образец.
3. Импортировать текст. Студия сохраняет исходник, готовит нормализованную
   версию и разбивает её на фрагменты. Произносимый текст можно править
   отдельно, в том числе сохранять `ё` и явные ударения.
4. Выбрать доступный способ озвучивания и сначала сделать пробу голоса.
5. Прослушать результат и запустить нужные фрагменты через очередь.
6. Когда у всех фрагментов есть принятый звук, скачать книгу одним WAV
   в порядке текста.

Данные по умолчанию хранятся в `%LOCALAPPDATA%\LocalAudiobookStudio`.
Закрытие вкладки не завершает сервер. Для завершения работы есть кнопка
«Выйти из приложения».

## Три способа работы с голосом

| Способ | Что используется | Что получается |
| --- | --- | --- |
| Озвучивание по короткому образцу | Подтверждённый фрагмент записи и его точный текст | Новая речь по образцу без обучения на полной записи |
| Дообучение VoxCPM2 | Подтверждённый корпус и LoRA-адаптер | Сохранения обучения, которые можно выбрать для синтеза |
| Ранний режим RVC | Отдельная модель преобразования голоса | Изменение тембра уже синтезированной речи |

RVC и LoRA для VoxCPM2 — разные модели и разные пути обработки. Сохранение
корпуса ещё не запускает обучение. Подтверждение короткого образца также
не означает, что модель обучилась на всей записи.

Для корпуса запись разбивается на клипы. Локальный Whisper создаёт черновую
расшифровку; её нужно прослушать и исправить, а неподходящие клипы исключить.
Затем сохраняется подтверждённая версия корпуса. Обучение VoxCPM2 привязано
к этой версии. В интерфейсе есть начало, остановка, продолжение, переход
к следующему проходу, новая линия обучения и история сохранений.
После перезапуска вычисления сами не возобновляются.

При синтезе из сохранения VoxCPM2 можно использовать опорную запись из его
подтверждённого корпуса. Задание закрепляет выбранное сохранение и опору;
ошибка не должна выдавать базовый голос как результат выбранной модели.

## Текущее состояние и ограничения

На одном локальном корпусе проверялись полный проход обучения, сохранение,
остановка и продолжение после перезапуска. Через очередь получены короткие
пробы из сохранённого адаптера, в том числе с опорным клипом. Эти проверки
подтверждают прохождение технической цепочки, но не качество клонирования
голоса. Сходство не принято: в пробах отмечались чужой тембр, слишком быстрый
темп и более глубокое звучание.

В текущей доработке в код добавлены:

- Seed для выбора вариации, число шагов синтеза и CFG.
- Темп экспортируемого аудио от 80 до 120%.
- Выбор подтверждённого опорного клипа или его отключение.
- Сохранение параметров вместе с результатом и повторное использование настроек.

Для этой доработки есть проверки клиента, сервера и Python-кода. В одной
короткой пробе с настоящим движком проверены выбор опорного клипа,
сохранение параметров и звука в истории, а также темп экспортируемого WAV
90%. Исходный звук длился 15,52 секунды, результат — 17,24 секунды.
Остальные сочетания параметров и длинные задания ещё требуют проверки.
Изменение параметров не гарантирует улучшения тембра или сходства.
Изменение темпа — дополнительная обработка аудио с приблизительным
сохранением высоты голоса; она может вносить артефакты. При 100% эта обработка
не применяется.

Полная аудиокнига, точность всех ударений, полнота чтения и удобство работы
с совершенно новой записью ещё требуют проверки. Прямой импорт M4A и экспорт
MP3 не реализованы. Для другого исходного текста пока нужен новый проект.
Ограничения длины фрагмента и времени обработки зависят от выбранного движка.

Текущий CPU-путь VoxCPM2 ограничивает работу двумя логическими процессорами,
13 ГиБ памяти для дерева вычислительных процессов и окном 300 секунд.
До запуска требуется 16 ГиБ свободной физической памяти, во время работы
сохраняется резерв 3 ГиБ.
Это условия допуска вычислений, а не обещание скорости на любом компьютере.
Подготовка и проверка файлов окружения тоже занимают время.

## Архитектура

Основная часть написана на C# и .NET 10. Браузерный интерфейс использует
React, TypeScript и Vite; метаданные проектов хранятся в SQLite.

| Каталог в `src/` | Назначение |
| --- | --- |
| `LocalAudiobookStudio.App` | Запуск Windows-приложения, локального сервера и внешних обработчиков |
| `LocalAudiobookStudio.App/ClientApp` | Интерфейс проектов, текста, корпуса, обучения и озвучивания |
| `LocalAudiobookStudio.Web` | HTTP API, локальные сессии и выдача файлов |
| `LocalAudiobookStudio.Application` | Сценарии подготовки, обучения и озвучивания |
| `LocalAudiobookStudio.Core` | Данные проекта, SQLite, работа с текстом и сохранёнными результатами |
| `LocalAudiobookStudio.Audio` | Чтение, проверка и обработка WAV/PCM |
| `LocalAudiobookStudio.Contracts` | Общие сообщения между частями приложения |
| `LocalAudiobookStudio.WorkerHost` | Управление отдельными вычислительными процессами |

Python-обработчики выделены по задачам: `TtsCorpusWorker` готовит корпус
и вызывает Whisper, `VoxCpmTrainingWorker` дообучает LoRA,
`VoxCpmInferenceWorker` синтезирует речь из сохранённого адаптера.
Ранний RVC-код находится в `workers/rvc/`.

Сервер ставит работу в очередь, а тяжёлые вычисления выполняются отдельными
процессами. Перед принятием результата проверяются ожидаемые файлы,
их контрольные суммы, формат аудио и связь с заданием. Это помогает
не перепутать результаты разных запусков и не принять оборванный файл
за готовую озвучку. Проверки файлов не заменяют прослушивание.

## Запуск и внешние ресурсы

Для сборки интерфейса нужны Windows 10/11 x64, PowerShell,
.NET SDK **10.0.401** и Node.js **24**. Версия .NET закреплена в `global.json`,
клиентские зависимости — в `package-lock.json`.

Из корня репозитория:

```powershell
.\scripts\app\Start-LocalStudio.ps1 -Configuration Release
```

Скрипт собирает сервер и клиент, затем запускает приложение. Первое
восстановление зависимостей может обращаться к NuGet и npm. Сам запуск
не устанавливает Python и не скачивает речевые модели. Без настроенных
движков доступен интерфейс, а вычислительные функции показывают недоступность.

Для вычислений отдельно нужны подходящее Python-окружение, зависимости,
исходники движка, веса моделей и подготовленный кеш базовых параметров
VoxCPM2. Пути и контрольные суммы задаются локальными дескрипторами.
Ресурсы проверяются перед запуском; случайный набор установленных пакетов
не считается готовым окружением.

У скрипта запуска есть отдельные параметры:

| Параметр | Для чего нужен |
| --- | --- |
| `-TtsCorpusRuntimeConfig` | Дескриптор обработки корпуса и расшифровки |
| `-VoxCpmTrainingRuntimeConfig` | Дескриптор VoxCPM2 для обучения и связанного синтеза |
| `-TrainingRuntimeConfig` | Дескриптор раннего RVC-режима |

Значением должен быть абсолютный путь к уже существующему файлу.
`scripts/voxcpm-training/New-LocalRuntime.ps1` помогает подготовить дескриптор
из имеющихся ресурсов и требует PowerShell 7. Он не устанавливает движок,
не загружает веса и не создаёт кеш базовых параметров. Настройка вычислений
пока остаётся отдельной технической задачей; приложение не готово
к установке вместе со всеми моделями одной командой.

В репозитории находятся исходники и проверки. Голосовые записи, частные
тексты, веса моделей, кеши и локальные Python-окружения в него не входят.
Права и лицензии внешних моделей и библиотек рассматриваются отдельно
от кода приложения.
